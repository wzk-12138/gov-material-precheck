返工闭环（图 1 红色链路）：清单口径不一致是反复跑的直接触发点。⑤ 人工比对发现缺项 → ⑥ 判「否」 → ⑪ 退回补正（保留原因）→ ⑫ 窗口解释并再收件 → ⑬ 群众再次跑动 → 回到 ③ 重新递交。现状补正率 36%，各节点等待与处理时间管理层尚未分别量出，因此无法据此排序优先环节（f00 f01 f10）。

系统与数据支撑带（贯穿全流程，秦芮负责）
  • 三套系统并行：政务办事平台、材料库、热线工单；账号权限独立维护，业务状态无统一视图，只能逐套核对（f30）。
  • 接口只读公开事项与授权材料，不能自动作出行政决定；预检结论只能作提示，最终判定靠人工（f32 f40）。
  • 数据质量：事项编码不同步、材料有效期与补正时间缺字段；先校验主编号 / 事件时间 / 版本字段，有歧义的记录进人工修复队列，不进入自动推荐样本（f31 f33）。
  • 时效：试点计划每天两次更新已授权业务状态，超一个更新周期标「待刷新」，不能作为实时承诺；接口中断时用带时间戳的上一份只读快照并显示「暂未更新」，重连后按业务编号去重补齐，人工流程照常（f34 f35）。

图 2 · 四条异常路径与转人工

逐条标明触发点、暂停 / 拦截方式、接手岗位与确认时点；四类均需标注触发原因、接手人、确认时间，不能只给一句模糊提醒（f44）。

A · 证件跨业务复用已过期，系统仍显示曾审核有效

触发点：⑤ 完整性预检 / ⑧ 专业审核 · 材料有效期字段缺失（f11 f31）

暂停 / 拦截
窗口暂停该建议，界面显示对应原记录与待确认字段；错误结果不得覆盖原记录；预检只提示，是否可拦截、拦截权限归属尚未书面确认。
接手岗位
业务审核员唐映秋核对后继续；涉及签核由傅景把关。
确认时点
标注触发原因、接手人、确认时间；对方确认接手才结束本岗待办。
证据：f11 f15 f31 f44 · 停止条件触及即暂停试点并由负责人复盘（f42）

B · 资料缺少依据

触发点：⑧ 专业审核 · 事项编码不同步、主编号 / 版本字段有歧义（f31 f33）

暂停 / 拦截
该记录不进入自动推荐样本，暂停建议并转入人工修复队列；歧义未消解前不对外解释结论。
接手岗位
唐映秋分派实际处理人；秦芮负责字段修复与最小字段集；跨岗须明确下一责任人。
确认时点
修复后按业务编号回写并留痕；超约定时限升级顾明岚；接手人确认时间入审计链。
证据：f33 f25 f44 f45 · 修复工时占比尚未核实

C · 两个版本冲突

触发点：⑧ 按生效日期与适用范围选版本时（f24）

暂停 / 拦截
唐映秋不自行合并、不选较宽松条款，把两个版本一并附上，暂停流程等待裁定。
接手岗位
数据与流程监督员傅景裁定；唐映秋不能代替其专业签核（f22）。
确认时点
裁定结论与签核人留痕；试点每周收集误判例子，由顾明岚确认改进负责人，先复测再更新规则版本。
证据：f24 f22 f44 f55 · 规则版本维护由业务负责人负责

D · 关键系统不可用 / 接口中断

触发点：任一依赖政务办事平台、材料库、热线工单的步骤（f30 f35）

暂停 / 拦截
继续使用带时间戳的上一份只读快照，界面显示「暂未更新」；现有人工流程照常运行，旧状态不得作实时承诺。
接手岗位
秦芮负责重连与去重补齐；窗口维持人工核对与解释。
确认时点
重连后按业务编号去重补齐，不反复触发同一待办；超过一个更新周期标「待刷新」。
证据：f35 f34 f44 · 快照时效阈值与允许降级事项尚未核实
四类异常的共性交接规则：异常先由业务审核员分派给实际处理人，超过约定时限再升级到服务中心主任；跨岗问题不能只写「已转交」，必须明确下一责任人。交接至少包含业务编号、当前版本、处理状态、未解决事项和接手人，对方确认接手才结束本岗待办。转人工须标注触发原因、接手人和确认时间（f23 f25 f44）。

待核实事项（按类型分组）

  • 验收口径：99% 一致率的样本、基准（线上清单还是窗口实际要求）、分歧裁定人；补正率分母、排除规则与统计周期。
  • 试点范围：两类非紧急事项具体由谁签字确认；首期历史资料回放范围；预检结果能否作为正式受理依据。
  • 权限与兜底：冲突场景「只提示」还是允许拦截、拦截权限归属；转人工接手人清单与确认时限；升级主任的时限；停止条件与验收签字形式。
  • 数据与系统：编码不同步 / 缺字段占比与修复工时；只读授权范围；快照时效阈值与允许降级事项；待刷新能否对外解释。
  • 留存与审计：90 天为暂定，真实期限按组织规则另定；改动是否强制填理由、是否保留历史版本；评价记录归集责任人。
  • 基线测量：节点级等待 / 处理时间、预检独立单量与耗时、返工与复核成本、脏数据占比、快照误判频次。
